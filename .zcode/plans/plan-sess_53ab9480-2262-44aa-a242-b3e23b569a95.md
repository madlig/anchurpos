# Rencana: Total Overhaul Role Owner — "Command Center Bisnis"

## Tujuan
Mengubah role owner dari app yang setengah rusak menjadi **command center monitoring** yang simpel, frictionless, dan bikin owner ingin buka tiap hari: pantau uang keluar-masuk, analisis bisnis, dan monitor produksi (SFM) — semua dalam 1-2 tap.

---

## A. Arsitektur Informasi Baru (Navigasi)

Bottom nav / sidebar owner diubah dari 4 → **5 item**, semua route berfungsi:

| Nav | Route | Fungsi |
|---|---|---|
| **Beranda** | `/owner/dashboard` | Command center (dibangun ulang total) |
| **Keuangan** | `/owner/reports` | P&L + Arus Kas + Jurnal (dipertahankan, label nav diubah) |

## B. API Baru (server-side)

### 1. `app/api/owner/overview/route.ts` (BARU) — panggilan tunggal dashboard
Satu endpoint `GET` yang meng-aggregate SEMUA yang dashboard butuhkan (frictionless = 1 request, bukan 5):
- P&L hari ini (omzet, hpp, profit, order count) — pola dari `/api/dashboard/today`
- Saldo bulan ini: `saldoBukuCash`, `saldoBukuBank` (dari pola `/api/reports/pnl`)
- Feed transaksi hari ini (dari `cashJournal` bulan ini, filter ke hari ini)
- Alert belum dibaca + count approval pending (opname/attendance/payroll)
- Item low-stock + produksi SFM hari ini
Authorization: `requireRole(req, ["owner"])`.

### 2. `app/api/reports/trend/route.ts` (BARU) — grafik 6 bulan
`GET ?months=6` → array `[{month, pemasukan, labaBotor, labaBersih, biayaOperasional}]` untuk 6 bulan terakhir. Loop pola agregasi `/api/reports/pnl` per bulan tapi return ringan (hanya angka, tanpa cashJournal). Menjalankan grafik tren recharts.

### 3. `app/api/owner/sfm-summary/route.ts` (BARU) — ringkasan SFM
`GET` → WO aktif (count + list ringkas), WO "stuck" (>3.5 jam), total good packs hari ini, yield rata-rata, item di freezer, batch/expiry yang dibuat hari ini. Read-only, pola query dari `app/api/sfm/work-orders/route.ts`. Auth: `["owner"]`.

### 4. Fix kecil: `app/api/dashboard/today/route.ts`
Ganti `totalCost` → `totalPrice` di baris 73 (konsistensi schema expenses). Sekaligus pastikan dipakai oleh overview.

## C. Halaman & Komponen

### C1. Dashboard baru — `app/owner/dashboard/page.tsx` (REBUILD TOTAL)
Command center dengan struktur berikut (mobile-first, sticky saldo):
1. **Saldo Bar sticky** (komponen `SaldoBar`) — Cash Laci + Bank + Net, auto-refresh saat window focus + tombol refresh.
2. **Hero P&L Hari Ini** — omzet besar, HPP, laba kotor (kartu gelap, gaya existing).
3. **Quick-Entry Kas** — 2 tombol besar "+ Pemasukan" / "+ Pengeluaran" → buka modal `QuickCashEntry` (post ke `/api/expenses` dengan `type`, kategori sesuai schema). Setelah submit, refresh dashboard. Ini inti "frictionless".
4. **Grafik Tren 6 Bulan** (komponen `TrendChart`, recharts) — garis pemasukan vs laba bersih, area biaya. Tap-to-detail.
5. **Feed Kas Hari Ini** (komponen `CashFeed`) — timeline kronologis keluar/masuk uang hari ini (in = hijau ↑, out = merah ↓), dari `overview.todayFeed`.
6. **Insight Cerdas** — kartu analisis otomatis: "Omzet hari ini X% vs kemarin", "Margin bersih Y%", "Z item stok menipis", "N WO butuh perhatian". To-the-point, 1 kalimat per insight.
7. **Approval & Alert mini-hub** — badge count + link ke `/owner/approval`.
8. Buang panggilan ke `/api/tasks` (tidak ada) → ganti feed nyata.

### C2. SFM Monitor — `app/owner/sfm/page.tsx` (BARU, read-only)
- Header dengan metrik eksekutif: WO aktif, di freezer, yield %, stuck.
- Daftar WO aktif (kartu): nomor WO, tipe, PIC crew, progress 5-step (visual bar), timer berjalan, batch code/expiry. **Tanpa tombol eksekusi** (read-only).
- Section "Produksi Hari Ini" — batch yang selesai, good packs, defect.
- Tombol "Lihat Audit Lengkap" → link ke halaman audit (reuse pola dari manager SFM tab audit, tapi read-only di route owner).
- Data dari `/api/owner/sfm-summary` + `/api/sfm/work-orders`.

### C3. Halaman menu "Lainnya" baru — `app/owner/more/page.tsx` (REBUILD)
Grid menu dengan link yang SEMUA ke `/owner/*` (berfungsi). Kartu profil + logout dipertahankan.

### C4. Halaman sub-menu read-only (baru, ringan — reuse API existing)

## E. Yang sengaja TIDAK dikerjakan (scope notes)
- **Tidak duplicate POS / master-data CRUD** untuk owner — itu operasional, tugas manager. Owner = monitoring.
- **Tidak menambah opening balance tersimpan** (perubahan model data terpisah) — saldo tetap "aliran bulan ini", dilabel jujur.
- **Tidak menambah websocket realtime** — "real-time" dicapai via refresh-on-focus + tombol refresh manual (cukup untuk UX monitoring).
- Halaman `/owner/reports` (Keuangan) **tidak diromak** dalam fase ini — sudah lengkap & bagus, hanya label nav diubah. Bisa dipoles di fase lanjut.

## Catatan teknis
- Ikut pola kode existing: monolitik per-page, `fetchWithAuth` dengan Bearer token, format rupiah `Intl.NumberFormat("id-ID")`, warna pink brand `#E85D8C`, komponen `lucide-react`.
- `recharts` sudah di `package.json` (^2.15.3) — tinggal pakai, tidak perlu install.
- Semua API baru pakai `requireRole` dari `lib/auth-middleware.ts` dengan `["owner"]` (atau `["owner","manager"]` bila masuk akal).
